**3つのアプローチ案：**

**A) シンプルなページ遷移型（推奨）**
各操作を独立したページで実装。`/snippets`（一覧）、`/snippets/[id]`（詳細）、`/snippets/new`（新規）、`/snippets/[id]/edit`（編集）。Next.js App Router に最も素直な設計で、TDD しやすい。ページ遷移ごとに再取得が発生するが、シンプルさと引き換えに十分な UX。

**B) モーダル型**
一覧ページを軸に、新規作成・編集・削除確認をモーダルで開く。ページ遷移なしでスムーズな UX になるが、Client Component が増えてフロントエンド側の状態管理が複雑になる。

**C) ページ遷移型 + API レイヤー分離**
A と同じページ構成だが、`/lib/api/snippets.ts` に API 呼び出しを集約し、カスタムフックで各ページからアクセスする。テストしやすく拡張性が高いが、ファイル数が増える。

  - エラー：サーバーエラーの場合は画面上部にエラーメッセージを表示する
- キャンセルリンク押下：
  - チェック：変更済み項目がある場合は「保存していません。戻りますか？」確認ダイアログを表示する
  - 正常：`/snippets/[id]` に遷移する
  - キャンセル：ダイアログを閉じて画面に留まる
- ローディング中（初期データ取得時）：スピナーまたは「読み込み中...」テキストを表示する
- スニペットが存在しない（404）：「スニペットが見つかりません」メッセージを表示する
