## シナリオ

「ユーザープロフィール編集画面」のブレインストーミングが完了したと仮定し、設計書を書き出す。  
画面は表示名・メールアドレスの編集、保存ボタン・キャンセルボタンを持つ。

## サブエージェントの出力

```markdown
# ユーザープロフィール編集画面 設計書

## 概要

ログイン中のユーザーが自分の表示名（display name）とメールアドレスを編集できる画面。Save ボタンで変更を保存し、Cancel ボタンで変更を破棄して前画面へ戻る。

---

## 前提条件

- バックエンド: Django REST Framework（`http://localhost:8000`）
- フロントエンド: Next.js（`nextjs-practice/`）
- 編集対象フィールド: `displayName`（表示名）、`email`（メールアドレス）
- 認証: ログイン済みユーザーのみアクセス可（認証トークンをリクエストヘッダーに付与）

## アーキテクチャ

### 全体方針

- データ取得は `useUser(id)` カスタムフック（SWR）に集約する。
- フォーム状態は `react-hook-form` が管理し、バリデーションは `zodResolver` 経由で Zod スキーマに委譲する。
- 保存処理は `useUpdateUser()` カスタムフックに集約し、ページコンポーネントはUIの制御に専念する。
