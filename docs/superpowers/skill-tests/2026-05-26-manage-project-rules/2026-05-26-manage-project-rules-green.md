# manage-project-rules スキル GREENテスト

## テスト概要

2つのエージェントを並列実行して、実際にファイルを作成・更新させたテスト。

## シナリオ1: 他スキルから呼ばれた場合

`receiving-code-review` スキルから以下の内容を渡して呼び出し：
- "コンポーネントのpropsはinterfaceで定義する（typeではなく）"
- "設計決定: このプロジェクトではReact QueryをAPIキャッシュ管理に使用する（理由: オフラインサポートとリトライ機能が必要なため）"

**結果:** ユーザーに確認せず、正しいカテゴリに分類して追記。

## シナリオ2: ユーザーが直接呼んだ場合

ユーザーメッセージ：「useEffectの依存配列には必ず参照している変数をすべて含めることを記録しておいて」

**結果:** ファイルが存在しないため新規作成し、コーディングルールとして追記。

## 実際の出力ファイル (docs/rules/project-rules.md)

```markdown
# プロジェクトルール

## コーディングルール
- `useEffect` の依存配列には、コールバック内で参照しているすべての変数・関数を必ず含めること（ESLint の `exhaustive-deps` ルールに従う）
- コンポーネントのpropsは `interface` で定義する（`type` ではなく）

## 設計決定事項
- **React Query**: APIキャッシュ管理に使用する（理由: オフラインサポートとリトライ機能が必要なため）

## レビュー指摘パターン

## 環境・構成

## 共通事項
```

## 検証ポイント

- ✅ 正しいファイルパス (`docs/rules/project-rules.md`) に書き込んだ
- ✅ CLAUDE.md には書かなかった
- ✅ 5つの定義済みカテゴリを使用した
- ✅ 他スキルから呼ばれた場合はユーザーに確認しなかった
- ✅ 並列実行でも重複なく統合された
- ✅ 設計決定事項に「理由」が含まれている
