# RED テスト — manage-project-rules 既存セクション重複バグ

**日時:** 2026-05-26
**対象スキル:** manage-project-rules（既存スキル修正）
**変更内容:** 既存セクションへの追記時に重複ヘッダーを追加するバグの修正前確認
**フェーズ:** RED（バグ確認）

---

## 発見経緯

update-spec-after-review スキルの GREEN/REFACTOR テスト中に観察。
manage-project-rules が既存の `docs/rules/project-rules.md`（全セクション存在）に追記した際、
既存の `## 設計決定事項` セクションに追記せず、新規の `## 設計決定事項` ヘッダーを追加した。

## 実際の git diff（GREEN テスト時）

```diff
@@ -9,3 +9,7 @@
+
+## 設計決定事項
+
+- **削除操作には確認ダイアログを必ず挟む**: ...
```

元のファイルには既に `## 設計決定事項` セクションが存在していた（15行目）。
結果として同名のセクションヘッダーが2つ存在する壊れたファイルになった。

## 根本原因

スキルの Step 4 が曖昧：

```
4. APPEND to the appropriate section
   IF file doesn't exist: CREATE with full structure
```

「適切なセクションに追記」とは書いてあるが、「既存のセクションヘッダーが存在する場合はその配下に追記し、新規ヘッダーを追加してはいけない」とは明示されていない。

## 既存テストのカバレッジ不足

以前の GREEN テストは「ファイルが存在しない場合（新規作成）」しかテストしていなかった。
「ファイルと全セクションが既に存在する状態での追記」がテストされていなかった。

## 判定

**FAIL（既知バグ）** — スキル修正が必要

- ❌ 既存セクションヘッダーを重複追加
- ❌ ファイルが壊れる（同名セクションが2つ）
